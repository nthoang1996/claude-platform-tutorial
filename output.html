# Detail Design SQL Extract Query

```sql
SELECT
    o.order_id AS OrderID,
    c.cust_name AS CustomerName,
    o.order_date AS OrderDate,
    o.total_amount AS TotalAmount
FROM
    ORDERS o
INNER JOIN
    CUSTOMERS c
    ON o.customer_id = c.cust_id
WHERE
    o.order_date >= DATEADD(DAY, -90, CAST(GETDATE() AS DATE))
    AND c.cust_id IS NOT NULL
ORDER BY
    o.order_date DESC,
    o.order_id ASC;
```

---

## Design Rationale & Assumptions Documented

### 1. **Join Condition Resolution**
- **Assumption:** Foreign key relationship between `ORDERS.customer_id` → `CUSTOMERS.cust_id`
- **Join Type:** `INNER JOIN` selected to exclude orders without matching customer records
- **Rationale:** Ensures data integrity; orphaned order records are filtered out

### 2. **Date Filter (90-Day Lookback)**
- **Assumption:** Business requirement implies recent order analysis
- **Implementation:** `WHERE o.order_date >= DATEADD(DAY, -90, CAST(GETDATE() AS DATE))`
- **Note:** Adjust syntax for non-SQL Server platforms:
  - **PostgreSQL:** `o.order_date >= CURRENT_DATE - INTERVAL '90 days'`
  - **MySQL:** `o.order_date >= DATE_SUB(CURDATE(), INTERVAL 90 DAY)`

### 3. **Null Customer Handling**
- **Assumption:** Exclude orders with null customer references
- **Implementation:** `AND c.cust_id IS NOT NULL`
- **Justification:** Maintains data quality; prevents incomplete customer profiles

### 4. **Column Mapping**
| Logical Name | Source Table | Source Column | Output Alias |
|---|---|---|---|
| OrderID | ORDERS | order_id | OrderID |
| CustomerName | CUSTOMERS | cust_name | CustomerName |
| OrderDate | ORDERS | order_date | OrderDate |
| TotalAmount | ORDERS | total_amount | TotalAmount |

### 5. **Ordering Logic**
- **Primary Sort:** `order_date DESC` (most recent orders first)
- **Secondary Sort:** `order_id ASC` (deterministic ordering within same date)
- **Compliance:** All columns in `ORDER BY` are present in `SELECT` clause

```sql
-- SQL Extract Query for Detail Design - Customer Transaction Data with Row-Level Security
-- Purpose: Extract transaction data with role-based access control and data classification filtering

SELECT 
    t.transaction_id AS Transaction_ID,
    t.amount AS Transaction_Amount,
    t.transaction_date AS Transaction_Date,
    CASE 
        WHEN u.role IN ('ADMIN', 'MANAGER') THEN t.description
        WHEN u.role = 'ANALYST' THEN NULL
        ELSE NULL
    END AS Transaction_Description,
    a.region AS Account_Region,
    u.role AS User_Role,
    a.data_classification AS Account_Data_Classification
FROM 
    TRANSACTIONS t
INNER JOIN 
    ACCOUNTS a ON t.account_id = a.account_id
INNER JOIN 
    USERS u ON t.created_by = u.user_id
WHERE 
    -- Row-Level Security: Access Control Logic
    (
        -- ADMIN role: sees all transactions
        u.role = 'ADMIN'
        OR
        -- MANAGER role: sees transactions only for accounts in their region
        (u.role = 'MANAGER' AND a.region = u.region)
        OR
        -- ANALYST role: sees aggregated data (limited to non-sensitive classifications)
        (u.role = 'ANALYST' AND a.data_classification IN ('PUBLIC', 'INTERNAL'))
    )
    AND
    -- Data Classification Access Control
    (
        -- ADMIN can access all classifications
        u.role = 'ADMIN'
        OR
        -- MANAGER can access PUBLIC, INTERNAL, and CONFIDENTIAL within their region
        (u.role = 'MANAGER' AND a.data_classification IN ('PUBLIC', 'INTERNAL', 'CONFIDENTIAL'))
        OR
        -- ANALYST can access only PUBLIC and INTERNAL (no CONFIDENTIAL data)
        (u.role = 'ANALYST' AND a.data_classification IN ('PUBLIC', 'INTERNAL'))
```

```sql
-- SQL Extract Query for Detail Design: Daily Sales Performance Metrics
-- Purpose: Extract and calculate daily sales metrics for past 12 months with trend analysis
-- Source: Sales_Transactions table
-- Target: Daily_Metrics table

WITH filtered_transactions AS (
  -- Step 1: Filter for completed transactions from past 12 months
  SELECT 
    transaction_date,
    amount
  FROM Sales_Transactions
  WHERE status = 'completed'
    AND transaction_date >= DATEADD(MONTH, -12, CAST(GETDATE() AS DATE))
),

daily_sales AS (
  -- Step 2: Aggregate transactions to daily level
  SELECT 
    transaction_date AS metric_date,
    SUM(amount) AS total_sales
  FROM filtered_transactions
  GROUP BY transaction_date
),

with_moving_avg AS (
  -- Step 3: Calculate 7-day moving average using window function
  SELECT 
    metric_date,
    total_sales,
    AVG(total_sales) OVER (
      ORDER BY metric_date 
      ROWS BETWEEN 6 PRECEDING AND CURRENT ROW
    ) AS moving_avg_7day
  FROM daily_sales
),

with_cumulative AS (
  -- Step 4: Calculate cumulative sales using running total window function
  SELECT 
    metric_date,
    total_sales,
    moving_avg_7day,
    SUM(total_sales) OVER (
      ORDER BY metric_date 
      ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
    ) AS cumulative_sales
  FROM with_moving_avg
),

with_mom_growth AS (
  -- Step 5: Calculate month-over-month growth percentage
  SELECT 
    metric_date,
    total_sales,
    moving_avg_7day,
    cumulative_sales,
    ROUND(
      ((total_sales - LAG(total_sales) OVER (
        ORDER BY DATEFROMPARTS(YEAR(metric_date), MONTH(metric_date), DAY(metric_date))
      )) / NULLIF(LAG(total_sales) OVER (
        ORDER BY DATEFROMPARTS(YEAR(metric_date), MONTH(metric_date), DAY(metric_date))
      ), 0)) * 100,
      2
    ) AS mom_growth_pct
  FROM with_cumulative
)

-- Step 6: Final SELECT with all mapped columns for Daily_Metrics table
SELECT 
  metric_date,
  total_sales,
  moving_avg_7day,
  mom_growth_pct,
  cumulative_sales
FROM with_mom_growth
ORDER BY metric_date ASC;
```

**Query Explanation:**

1. **filtered_transactions CTE**: Filters `Sales_Transactions` for `status = 'completed'` and transactions within the past 12 months, selecting only `transaction_date` and `amount`.

2. **daily_sales CTE**: Groups filtered transactions by `transaction_date` and sums amounts to create daily totals (`total_sales`).

3. **with_moving_avg CTE**: Calculates the 7-day moving average using `AVG(total_sales) OVER (ROWS BETWEEN 6 PRECEDING AND CURRENT ROW)` window function.

4. **with_cumulative CTE**: Computes cumulative sales using `SUM(total_sales) OVER (ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)` for a running total.

5. **with_mom_growth CTE**: Calculates month-over-month growth percentage by comparing each day's sales to the same day in the previous month using `LAG()` window function.

6. **Final SELECT**: Returns all mapped columns (`metric_date`, `total_sales`, `moving_avg_7day`, `mom_growth_pct`, `cumulative_sales`) ordered by `metric_date` in ascending order.
